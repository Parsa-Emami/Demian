# Phase 18 — Smart quiet-hour discounts

Stacked on Phase 17 #104 (exact-head backend CI passed). Original Phase 18 scope: smart discounts for quiet hours. Chosen implementation: owner-approved rules, not an AI demand predictor; physical occupied/total seats are manually attested at publication. No POS/occupancy integration exists, and QR launches cannot establish actual footfall. No invented occupancy data or automatic financial activation. The owner can immediately pause new claims if occupancy changes; existing issued terms remain valid until expiry. Real business policy, approved legal publications, phone OTP gateway, HTTPS, scheduler and capacity validation remain external prerequisites.

Default disabled: DEMIAN_QUIET_HOURS_ENABLED=false; independently require cafe redemption and approved coupon policy, configured OTP and legal gates. Set DEMIAN_QUIET_HOURS_DAILY_BUDGET_MINOR, DEMIAN_QUIET_HOURS_COST_CEILING_BPS and DEMIAN_QUIET_HOURS_MARGIN_FLOOR_BPS only with actual owner approval. Fixed conservative defaults max 10% / 40% occupancy, <=20 coupons per offer, <=4 hours, same Tehran date, starts now or within 30 minutes of observation. Super-admin existing coupon-management capability + password + CSRF, immutable terms, staff audit, branch with active staff, no overlapping windows even if paused. Maximum liability = issue capacity x cap; global day reservation across all branches serialized in DB, including paused/expired offers, with no recycling. Integer-only discounts and minimum-basket contribution-margin guard at creation and actual basket. Cost ceiling is an approved assumption not measured profit. Report actual coupon-bearing receipts, not incremental revenue.

Player wallet shows active offerings from authenticated no-store API; explicit claim, 48-hour verified number, current legal acceptance where required, one per Tehran day per account and day-keyed verified telephone digest across branches even after erasure. No claim from QR alone, no leaderboard or referral effects. Player row and singleton serialized; identity/day uniqueness; repeat same owner+offer returns existing coupon id without minting. Distinct SIMs/devices can still represent same person, bounded budget and physical cashier only limit exposure. No secret in claim response; existing wallet reads bearer code privately. Redemption uses existing atomic cashier receipt path with extra frozen terms, branch and time checks; idempotent retries of existing receipt work unchanged. Pausing/turning off issuance does not revoke valid issued coupons; emergency revoke uses existing workflow. No online redemption, no coupon stacking. New financial data are immutable, privacy export allowlisted claim fields; player deletion nulls link and revokes coupon via existing erasure, day-keyed digest retained 90 days, scheduler removes it; coupon and receipt records retained for accounting. No new raw phone/device tracking. Review privacy notice and retention before enablement. UI uses local router/game-ui-ux skill, native controls and wallet lifecycle generation guard; engine unchanged. Static playable rebuild must pass existing CI.
