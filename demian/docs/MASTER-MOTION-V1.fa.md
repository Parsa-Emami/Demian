# الگوی مادر حرکت و لودینگ دمیان

تاریخ: ۶ نوامبر ۲۰۲۶. خروجی این مرحله، قرارداد مشترک ۱۲ شخصیت، نمونه‌بردار ژست مفصلی، اتصال به چرخهٔ اجرای فعلی، صفحهٔ مقایسه و لوگوی لودینگ اولیه است.

## استفاده

از منوی اصلی «مقایسهٔ الگوی حرکت» را باز کنید. حنا، آیناز، امین و حسین هم‌زمان نمایش داده می‌شوند. در هر کارت، سمت چپ تصویر اطلس فعلی شخصیت و سمت راست الگوی مادر مفصلی است. با انتخاب حالت، سرعت، جهت و فاز، همهٔ کارت‌ها هم‌زمان تغییر می‌کنند. توقف، یک فریم جلو، شروع از ابتدا و انتخاب هر یک از ۱۲ شخصیت در دسترس است.

دکمهٔ «بال‌ها و همراه‌ها» اوزودی، امیررضا، دریا و تیام را کنار هم می‌گذارد. نقاط طلایی روی الگو محل تماس پا هستند. در حالت کاهش حرکت، مقایسه متوقف باز می‌شود و کنترل دستی فریم فعال می‌ماند.

این مرحله مبنای بازبینی حرکت است. تصویرهای فعلی شخصیت‌ها همچنان از اطلس‌های اختصاصی V14 می‌آیند؛ اسکلت مشترک به معنی بازسازی کامل تمام تصویرها نیست. مطابق ترتیب توافق‌شده، انتقال هنری پوسته‌ها به حرکت مادر پس از بازبینی نمونه‌ها انجام می‌شود. در این انتشار ادعای یکسان‌شدن تصویری مفاصل تمام اطلس‌های قبلی یا ساخت حرکت واقعی هشت‌جهته مطرح نمی‌شود.

## خانواده‌ها

| خانواده | شخصیت‌ها | ویژگی |
|---|---|---|
| female-base-v1 | دریا، ستایش، نگار، تیام، حنا، آیناز | یک rig و یک مجموعه قواعد ژست؛ خم بدن، دامنهٔ دست و حرکت متقابل شانه‌ها از خانواده خوانده می‌شود |
| male-base-v1 | اوزودی، امیررضا، ارسل، ایمان، امین، حسین | یک rig و یک مجموعه قواعد ژست؛ بدن بالدارها هم از همین خانواده استفاده می‌کند |

هویت، لباس، صورت، دیالوگ و قابلیت اختصاصی هر شخصیت از خانوادهٔ حرکت جدا هستند. خانواده‌ها انتخاب صریح هنری در داده‌اند و از نام کاراکتر در زمان اجرا حدس زده نمی‌شوند.

| ویژگی اختصاصی | قرارداد |
|---|---|
| بال اوزودی و امیررضا | اتصال به chest؛ حرکت و بازشدگی ثانویه؛ بازشدگی بیشتر در پرش و جمع‌شدن در اسلاید؛ بدون تغییر اسکلت پایه یا برخورد |
| همایون تیام | اتصال به shoulderNear؛ جابه‌جایی تزئینی مستقل از hitbox |
| پیشی دریا | اتصال نمایشی نزدیک زمین؛ برخورد رقابتی مستقل |

تصویر فعلی بال و همراه در اطلس‌ها baked است. در سمت الگوی مفصلی، محل اتصال و وضعیت لایهٔ مستقل نمایش داده می‌شود؛ این نمایش یک ابزار بررسی rig است و تصویر نهایی بال یا همراه محسوب نمی‌شود.

## معماری اجرایی

منبع مرکزی `resources/game/character-motion.json` شامل فهرست شخصیت‌ها، نسبت‌های rig، دو خانواده، کلیپ‌های پایه، نقاط اتصال و وضعیت انتقال است. JavaScript و رجیستری ابزارهای Python از همان فایل می‌خوانند.

`MasterMotionLibrary` ژست را به‌صورت تابع خالص نمونه‌برداری می‌کند. پا در بخش تماس روی زمین می‌ماند و در بخش بازگشت بلند می‌شود. زانو با IK دوبخشی حل می‌شود؛ هدف خارج از دسترس محدود می‌شود تا NaN یا تغییر طول استخوان ایجاد نشود. حرکت دست‌ها مخالف فاز پاهاست. ورودی حالت، فاز، پیشرفت و جهت جدا از منطق شبیه‌سازی است.

`MasterMotionController` دادهٔ هویت را به خانواده متصل می‌کند، ژست و لوازم ثانویه را نگه می‌دارد و رخدادهای تماس پا را فقط هنگام عبور از مرز فاز تولید می‌کند. پیشروی مستقل آن بر اساس مسافت واقعی و سقف cadence محدود است. توقف پشت مانع، فاز قدم را جلو نمی‌برد.

`FrameAnimator` برای کاراکترهای ثبت‌شده یک controller مادر دارد. `advanceCharacterAnimation` آن را با همان فاز حرکت اطلس و پیشرفت حالت همگام می‌کند. بنابراین هر دو مسیر `CanvasCharacterAvatar` و `SpriteCharacter` دادهٔ مادر دارند. شخصیت سفارشی ناشناخته از مسیر موجود خود ادامه می‌دهد.

نمایش فعلی بازی همچنان مالک فریم‌های اختصاصی، مقیاس بدن و محور پای V14 است. فیزیک، قواعد رانر، امتیاز و بازپخش تغییر نکرده‌اند. controller مادر برای فریم‌به‌فریمِ بازبینی و مرحلهٔ بعدی retargeting آماده است؛ تغییر پوست باید منبع هنری و کنترل تصویری خودش را داشته باشد.

`MotionComparisonScreen` یک modal در ScreenManager فعلی است. بازکردن مجدد، تغییر سریع شخصیت و پایان بارگذاری قبلی با generation و token کنترل می‌شوند. خروج از صفحه، RAF و مرجع کارت‌ها را آزاد می‌کند. برای کاهش هزینهٔ تصویر، نمایش گوشی از lite و دسکتاپ از runtime استفاده می‌کند؛ حداکثر چهار کارت هم‌زمان نگه داشته می‌شوند.

## ساخت و اعتبارسنجی

```bash
npm ci
npm run build:static
npm run validate:motion
npm run test:ci
npm run validate:final
npm run validate:ui-layers
npm run validate:skills
npm run validate:characters:v14
npm run validate:build
```

ساخت، قرارداد عمومی `public/assets/characters/master-motion-v1.json` و اتصال خانواده در roster و ۱۲ motion profile را تولید می‌کند. hash منبع در خروجی‌ها ثبت و در CI بررسی می‌شود. تغییر مستقیم فایل تولیدی بدون تغییر منبع و بازسازی، معتبر نیست.

تست‌های جدید برابری دقیق مفاصل اعضای خانواده، تفاوت دو خانواده، طول ثابت استخوان، ثبات تماس پا در تمام چرخه، فاز بر اساس مسافت، توقف، جهت معکوس، رخداد تماس در wrap و جدایی بال‌ها و همراه‌ها را بررسی می‌کنند. تست یکپارچگی، اتصال controller به اطلس‌های اجرایی هر ۱۲ شخصیت را بررسی می‌کند.

ابزار `tools/check_master_motion.mjs` خروجی استاتیک را در مرورگر بررسی می‌کند. برای اجرا، Playwright نصب‌شده و مرورگر لازم است. مسیر ماژول، مرورگر، پوشهٔ انتشار و پوشهٔ شواهد با متغیرهای `DEMIAN_PLAYWRIGHT_MODULE`، `DEMIAN_BROWSER_EXECUTABLE`، `DEMIAN_QA_RELEASE_DIR` و `DEMIAN_QA_OUTPUT_DIR` قابل تعیین‌اند.

## لودینگ اولیه

همان فایل `assets/environments/cafe-runner-v1/wordmark.png` که در شروع رانر دیده می‌شود، در لودینگ اول استفاده شده است. تصویر در HTML اولیه قرار دارد، preload و اولویت بالا دارد، نسبت اصلی خود را حفظ می‌کند و برای نمایش به راه‌اندازی JavaScript وابسته نیست. حرف D متنی قبلی برداشته شده و نوار پیشرفت، وضعیت دسترس‌پذیر دارد.

آزمون اولین نمایش با معطل‌کردن درخواست bundle جاوااسکریپت انجام می‌شود؛ وجود لوگوی بارگذاری‌شده و نبود نشان متنی قبلی پیش از آزادکردن script بررسی می‌شود. تصاویر و نتیجهٔ مرورگر در `docs/validation/master-motion-v1` هستند.

## محدودهٔ شواهد

آزمون مرورگر با Chromium بدون رابط و رندر نرم‌افزاری SwiftShader انجام می‌شود؛ حالت گوشی، شبیه‌سازی viewport و لمس است. این نتیجه اندازه‌گیری نرخ فریم، تأخیر لمس، باتری یا دمای گوشی فیزیکی نیست. دادهٔ دو خانواده و اتصال ۱۲ شخصیت پیاده شده است؛ پذیرش هنری ژست‌ها و تبدیل پوسته‌های همهٔ شخصیت‌ها مرحلهٔ بعد از بازبینی نمونه‌هاست.
