# Phase 17 — Dedicated cafe table QR codes (P1)

Recovered original roadmap: Phase 15 referrals; Phase 16 exclusive cafe events; Phase 17 table QR; Phase 18 smart quiet-hours discounts; Phase 19 business intelligence; Phase 20 commercial pilot and continuous optimization. Prior PR #103 implemented a provisional analytics dashboard instead of original Phase 16; preserve it as early Phase 19 work. Exclusive cafe events remain outstanding under the original Phase 16 scope. This PR implements Phase 17 independently, stacked on #103 to preserve existing work. Original roadmap supplied the heading, not detailed deliverables; below are implementation choices.

Super-admin only inventory (existing report.global permission, active staff branch, label, randomly generated 128-bit opaque code, max 500 tables), password step-up and CSRF for create, disable, enable and rotate; audited mutations without raw code. Old rotated links no longer work; disabled tables do not resolve. Native print-friendly SVG generated locally with QR version 6-L byte mode, mask 0, 4-module quiet zone; maximum 134 UTF-8 bytes, same independent reference-matrix test vector as Phase 15. Public landing is deliberately registered before API-only guard, supports phone screens, requires explicit POST to launch. GET does not count crawlers or previews. Session-bound CSRF + 10-minute nonce, unique marker inside table-row transaction avoids replay double count; no durable user IDs, raw IP, phone, fingerprint, clickstream, or third-party trackers added. Existing framework session/rate limiter and server access logs still apply. Count is aggregate launch clicks, NOT proven scans, footfall, verified customers, registrations, or physical presence. Copied QR can be used remotely; never grants a score, discount, reward, reservation or staff authorization. Day caps are 2000/table, report last 30 Tehran dates including today. Nonce retention 24h, aggregates 365 days via existing Cron. Inventory and history retained for audit, not deleted on retirement.

Configuration: DEMIAN_TABLES_ENABLED=false by default; DEMIAN_TABLE_PUBLIC_BASE=https://actual-api-host[/deployment-prefix] (no trailing /t), DEMIAN_TABLE_GAME_URL=https://actual-game-host/path/ (fixed operator-reviewed destination, no query/fragment/credentials; no user-controlled redirect). Configure HTTPS, persistent shared cache/session, Cron, migrate and confirm actual printed domain before enabling. The route is /t/{opaque-code}; dashboard /cashier/admin/tables. No actual table names or host settings invented. Do not print until legal privacy notice, physical scan test and rollback plan reviewed. Keep QR public, never use it as an identity credential, and replace rotated printed signage. Run php artisan arcade:tables:prune (scheduled daily). No changes to engine, assets, public static frontend or reward logic; local router and game-ui-ux used for responsive server-rendered screens. Tests cover matrix, route authorization, rotation, revocation, launch deduplication, timezone, destination validation and no reward. CI and actual phone/printed scan acceptance still required. No deployment.
