# Phase 11 — XP and Loyalty

Policy loyalty-xp-v1. Private append-only weekly grant derived exclusively from Phase 10 phone-verified sealed replay evidence and breakthrough badges. 100 XP for a qualifying week, 25 per additional distinct game up to two, 50 once for a verified breakthrough, 25 if immediately preceding calendar week has a sealed XP grant. Maximum 225 per account/week. More runs, higher raw score, idle time, multiple rules versions and device count cannot increase the caps. No loss from inactivity. Late historical seal receives base/variety only, no retroactive continuity/progress bonus. Not proof of human uniqueness. Mission XP is explicitly disabled until verified server mission evidence and a versioned budget policy are implemented in Phase 12.

One row per player/period with unique DB constraint, frozen policy, source digest and integer component ledger; in same serialized settlement transaction as Phase 10, not directly reachable by HTTP. No historic inferred backfill. Derived lifetime XP, level = 1 + floor(XP/250); thresholds Member 0, Regular 500, Loyal 1500, VIP 3000, Ambassador 6000. Tier progression independent of skill leagues and prize rank. XP is nontransferable, nonpurchasable and not convertible to vouchers, privileges, currency or discounts. Financial budget zero. Existing coupon rules unmodified.

Private rate-limited GET /player/loyalty, authenticated player only, no-store, last 12 grants and lifetime total, no public board. Persian accessible details panel, lifetime tier and level meter, weekly component history. Clear on account recovery/erasure and screen lifecycle; discard stale response. Privacy export allowlist, cascade erasure. No client claim, mutation, receipt or device fingerprint. Source SHA and player ID not included in history. CI tests: caps, tier boundaries, unverified player, repeated seal, six-week total, private API and erasure. Actual economic and device UAT not claimed.

## Multi-SIM / multi-device fraud
Phone OTP proves possession, not a unique human. Keep low-risk play accessible and keep XP nonfinancial; people can still create distinct verified accounts. Do not block shared IP/device or infer a person solely from browser fingerprints. Proposed separate in-cafe reward-identity policy: a staff-attested membership, authenticated account association before eligibility, auditable approval/revocation, unique membership/period financial award constraint, atomic redemption, manual review and appeal, duplicate-link checks and resistance to colluding staff. A physical visit alone cannot mathematically prove uniqueness; stronger ID verification should be proportionate, privacy-reviewed and lawful, not collect national ID by default. No silent identity linkage, biometric processing or new phone surveillance in this phase. Existing weekly single-account/verified-phone constraints remain and multi-number holders can still circumvent them; require approved membership policy before introducing additional financial benefits.

No production deployment. Mandatory authored PNG gate remains. Applied repository skills: router/save-systems (existing persistence conventions). New static build remains CI-derived. Next Phase 12: server-verified daily/weekly missions.
