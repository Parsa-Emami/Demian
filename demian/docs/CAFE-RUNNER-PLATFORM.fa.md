# کافه‌ران و پلتفرم امتیاز دمیان

تاریخ: ۵ نوامبر ۲۰۲۶. این سند قرارداد ادامهٔ توسعهٔ بازی و راهنمای استقرار بخش جدید Laravel است. نسخهٔ موتور و وابستگی‌های پروژه حفظ شده‌اند.

## نتیجهٔ پیاده‌سازی

| درخواست | رفتار پیاده‌شده |
|---|---|
| دویدن داخل کافه | تصویر اختصاصی بر اساس تصاویر واقعی کافه، پارالاکس، کف متحرک، نور روز و شب، ذرات محدود و سایه |
| عناصر مرجع | کانتر با کاشی سبز، دستگاه قهوه، کتابخانه، میز و صندلی چوبی، آینه، گیاه و چراغ آویز؛ لوگوی ارسالی در صفحهٔ شروع |
| موانع مرتبط | صندلی و جعبهٔ قهوه برای پرش؛ چراغ آویز برای اسلاید |
| هشت شخصیت | Tiam، AmirReza، Hanna، Ainaz، Arsal، Iman، Amin و Hossein؛ شیت تازهٔ راه‌رفتن، دویدن و پرش با مرجع حرکتی Darya، Uzudi و Setayesh |
| هویت شخصیت‌ها | پوشش، صورت، بال‌ها، همایونِ تیام، دیالوگ‌ها و اسلایدهای اختصاصی حفظ شده‌اند |
| سختی آغازین | preset رانر برابر ۶ از ۱۰؛ افزایش پیوستهٔ سرعت و فشار موانع، با سقف مشخص |
| سایر مینی‌گیم‌ها | پایهٔ Arcade از سختی ۶ شروع و با زمان فشار تولید مانع را افزایش می‌دهد؛ preset تتریس از سطح ۶ آغاز می‌شود |
| لیدربورد | روزانه، هفتهٔ ISO و همیشگی برای Dino Run؛ رکوردهای همین مرورگر در حالت تمرینی |
| اعتبارسنجی | محاسبهٔ امتیاز از بازاجرای ورودی‌ها روی سرور، بدون اعتماد به امتیاز ارسالی مرورگر |

در کاتالوگ فعلی فقط Open World و Dino Run فعال هستند. Open World تجربهٔ اکتشاف است و امتیاز رقابتی ساختگی برای آن تعریف نشده است. بازی‌های آرشیوشده با این تغییر دوباره فعال نشده‌اند؛ برای رتبه‌بندی آنلاین هر بازی تازه باید verifier اختصاصی آن نیز پیاده شود.

## معماری

موتور موجود Canvas 2D و سرویس‌های فعلی ورودی، انیمیشن، تنظیمات، چرخهٔ بازی و رابط حفظ شده‌اند. مهاجرت به Phaser یا افزودن سه‌بعدی برای این کار ضروری نبود. Laravel موجود به یک بخش مستقل Arcade مجهز شده است؛ ایجاد پروژهٔ دوم یا چند سرویس جدا در این مقیاس هزینهٔ نگهداری و هماهنگی بی‌دلیل داشت.

| مرز | مسئولیت |
|---|---|
| DinoRunModel | شبیه‌سازی ثابت، برخورد، سرعت، امتیاز، مانع و پایان بازی |
| DinoRunEnvironment | تصویر و دکور، نور، پارالاکس و ذرات؛ بدون تغییر فیزیک |
| RunnerReplay | ثبت تغییر ورودی‌ها بر اساس tick با سه بیت پرش، نگه‌داشتن پرش و اسلاید |
| ArcadeLeaderboardService | هویت مهمان، نشست، ثبت رکورد، تلاش دوباره و ذخیرهٔ محلی |
| LeaderboardScreen | نمایش رتبه‌ها، نام نمایشی، بازه و حالت محلی |
| FormRequest و Middleware | اعتبارسنجی شکل درخواست، احراز هویت توکنی و محدودیت حجم |
| ArcadeRunService | تراکنش پایان نشست، جلوگیری از ثبت تکراری و به‌روزرسانی بهترین امتیاز |
| RunnerReplayVerifier | بازاجرای مستقل فیزیک و برخورد در PHP |
| LeaderboardService | بازه‌های UTC و خواندن بهترین رکورد هر بازیکن با ترتیب پایدار |

قوانین مشترک در `resources/game/runner-rules.json` قرار دارند. کلید نسخهٔ آن `cafe-runner-v1` است. تغییر مؤثر بر امتیاز یا برخورد باید نسخهٔ قوانین را تغییر دهد تا امتیازهای ناسازگار در یک جدول مقایسه نشوند.

سختی رانر از رابطهٔ `6 + 4 × (1 − exp(−t / 90))` پیروی می‌کند. سرعت از ۳۳۵ پیکسل منطقی بر ثانیه با رشد ۲٫۸ شروع و در ۵۶۰ متوقف می‌شود. حداقل فاصلهٔ زمانی موانع به‌تدریج از ۱٫۱ به ۰٫۸۸ ثانیه نزدیک می‌شود و جزء تصادفی محدود نیز دارد. «۶ از ۱۰» preset طراحی است؛ کالیبراسیون ادراکی آن با بازیکنان واقعی هنوز نیازمند playtest انسانی است.

عرض مسیر هنگام شروع نشست به سرور ارسال و ثابت می‌شود؛ تغییر اندازهٔ نمایشگر مسیر همان نشست را تغییر نمی‌دهد. عرض نیز در دادهٔ رکورد نگه داشته می‌شود. میدان دید دستگاه‌ها یکسان نیست و برای رقابت رسمی می‌توان دسته‌های جداگانهٔ اندازهٔ نمایشگر تعریف کرد.

## داده‌ها

| جدول | دادهٔ اصلی و قیود |
|---|---|
| arcade_players | UUID، نام نمایشی، هش یکتای توکن؛ خود توکن ذخیره نمی‌شود |
| arcade_runs | بازیکن، UUID درخواست، بازی، نسخهٔ قوانین، شخصیت، seed، عرض، زمان‌ها، وضعیت و نتیجهٔ سرور |
| arcade_replays | یک payload ورودی برای هر نشست تأییدشده با کلید خارجی و محدودیت نگهداری |
| arcade_leaderboard_entries | بهترین رکورد هر بازیکن برای هر بازی، نسخه و بازه؛ قید یکتایی و شاخص خواندن رتبه‌ها |

شروع تکراری با همان request_id همان نشست را برمی‌گرداند. استفادهٔ دوبارهٔ آن شناسه با مشخصات متفاوت خطای ۴۰۹ می‌دهد. پایان تکراری با همان هش بازپخش نتیجهٔ قبلی را برمی‌گرداند؛ شواهد متفاوت برای نشست پایان‌یافته رد می‌شوند. قفل بازیکن و نشست و نوشتن رکوردها در یک تراکنش از دو بار ثبت جلوگیری می‌کند.

بازهٔ روزانه و هفتگی بر اساس زمان شروع نشست در UTC است؛ هفته از استاندارد ISO پیروی می‌کند. در امتیاز مساوی، زمان زودتر و سپس شناسهٔ ورودی ترتیب را پایدار می‌کنند. نام نمایشی قابل تکرار است؛ UUID هویت واقعی مهمان را جدا می‌کند.

## API

پیشوند: `/api/v1/arcade`.

| روش و مسیر | احراز هویت | کاربرد |
|---|---|---|
| GET /rules | عمومی | قوانین و فهرست شخصیت‌ها |
| POST /players | عمومی و محدودشده | نام نمایشی و صدور توکن مهمان |
| PATCH /player | Bearer | تغییر نام نمایشی |
| POST /runs | Bearer | request_id، game_id، character_slug، track_width و rules_version |
| POST /runs/{run}/complete | Bearer و مالک نشست | ticks و transitions؛ امتیاز کاربر مبنا نیست |
| GET /leaderboards/dino-run | عمومی | period از all، daily، weekly؛ limit حداکثر ۵۰ |

ورودی‌ها مرتب و فشرده هستند: هر تغییر `{tick, mask}` است. سقف اجرا ۵۴۰۰۰ tick در ۶۰ هرتز، سقف تغییر ورودی ۱۲۰۰۰ و سقف بدنهٔ درخواست ۲۵۶ KiB است. نشست باید در برخورد یا سقف زمان واقعاً پایان یابد. ادامه پس از مرگ، پایان زودرس، ترتیب نامعتبر، نشست منقضی، مالک متفاوت و زمانی جلوتر از ساعت سرور پذیرفته نمی‌شوند.

این روش دستکاری مستقیم عدد امتیاز را حذف می‌کند؛ تشخیص همهٔ بات‌ها یا اثبات حضور انسان نیست. توکن مهمان به همین مرورگر تعلق دارد و با پاک‌کردن حافظه قابل بازیابی نیست. ورود حساب کاربری و بازیابی بین دستگاه‌ها بخشی از این تغییر نیست.

## دارایی و انیمیشن

اصل شیت‌های پیشین حفظ شده و شیت جدید هر شخصیت با نام `source-v14/locomotion-v15.png` و فایل provenance شامل هش، منبع و چیدمان نگه داشته می‌شود. هشت ستون و سه ردیف برای راه‌رفتن، دویدن و مراحل پرش هستند. دو چرخهٔ شخصیت‌هایی که قبلاً چرخهٔ دوگانه داشتند به‌صورت تکرار صریح یک stride کامل حفظ شده‌اند تا سرعت دست و پا دو برابر نشود.

بسته‌ها همان ۶۷۲ نام فریم و قرارداد اطلس V14 را دارند. نرمال‌سازی با یک مقیاس برای هر clip، محور پا، اسلاید مستقل و interpolation بدون دو سیلوئت انجام می‌شود. نسخه‌های runtime، lite و detail سقف حافظهٔ قبلی را حفظ می‌کنند. پرش شامل جمع‌کردن واقعی زانو است؛ کنترل کیفیت علاوه بر قدِ بازیابی، اندازهٔ صورت نسبت به راه‌رفتن را کنترل می‌کند تا کوتاه‌شدن طبیعی سیلوئت با کوچک‌شدن کل بدن اشتباه نشود.

ساخت مجدد:

```bash
python3 -m pip install -r tools/requirements-character-art.txt
python3 tools/build_character_pack_v14.py --characters tiam amirreza hanna ainaz arsal iman amin hossein
python3 tools/build_runtime_character_packs.py --characters tiam amirreza hanna ainaz arsal iman amin hossein
python3 tools/validate_character_pack_v14.py
```

ابزار محلی `game-dev` در محیط اجرا موجود نبود و نشست تأییدشدهٔ Meshy نیز در دسترس نبود. دارایی‌های این تغییر دوبعدی‌اند و با تولید تصویر، بسته‌بندی محلی و کنترل‌های خود پروژه ساخته شده‌اند؛ مدل سه‌بعدی یا خروجی Blender ادعا نشده است.

## استقرار Laravel

پیش‌نیاز: PHP سازگار با composer.lock، افزونه‌های موردنیاز Composer، HTTPS و MySQL 8 یا MariaDB سازگار. آزمایش محلی خودکار با SQLite انجام شده است؛ اجرای آزمون روی موتور تولید پیش از انتشار عمومی لازم است.

```bash
composer install --no-dev --prefer-dist --optimize-autoloader
php artisan migrate --force
php artisan optimize
php artisan schedule:run
```

Document root باید پوشهٔ `public` باشد. APP_KEY واقعی، APP_ENV=production و APP_DEBUG=false را روی میزبان تنظیم کنید. دسترسی نوشتن storage و bootstrap/cache لازم است. cron استاندارد Laravel باید هر دقیقه scheduler را اجرا کند. `arcade:prune` روزانه نشست‌های رهاشده را منقضی و payload بازپخش قدیمی‌تر از ۳۰ روز را حذف می‌کند؛ نتیجه، هش و بهترین امتیاز باقی می‌ماند. تهیهٔ پشتیبان دیتابیس و پایش `/up` مسئولیت میزبان است.

در ارائهٔ مستقیم Laravel، متای `demian-arcade-api` از URL برنامه پر می‌شود. GitHub Pages کد PHP اجرا نمی‌کند. برای اتصال خروجی استاتیک به میزبان Laravel:

```bash
DEMIAN_ARCADE_API_URL=https://api.example.com/api/v1/arcade npm run build:static
```

روی Laravel مقدار `DEMIAN_ARCADE_ALLOWED_ORIGINS` را دقیقاً برابر origin سایت استاتیک، بدون path، قرار دهید. برای چند origin از کاما استفاده کنید. توکن در Authorization ارسال می‌شود و کوکی بین مبدأها فعال نیست. endpoint فقط یک نشانی عمومی API است و نباید حاوی اطلاعات محرمانه باشد.

بدون endpoint، بازی و جدول «این دستگاه» فعال می‌مانند. خرابی اتصال، امتیاز را جهانی نشان نمی‌دهد. درخواست شروع دارای seed صریح نیز تمرینی است. بعد از پایانِ یک نشست آنلاینِ معتبر، خطای موقت شبکه امکان تلاش دوباره دارد.

## شواهد و ادامهٔ کار

نتیجهٔ اجراها در `docs/validation/cafe-runner-platform` و فایل‌های گزارش هم‌جوار ثبت می‌شود. چهار fixture قطعی بین JavaScript و PHP، ثبت تکراری، مالکیت، انقضا، ساعت سرور، دادهٔ ناقص و قواعد بازه آزمایش می‌شوند. تست خودکار مسیرهای چند seed را تا سرعت نهایی بررسی می‌کند. دستگاه فیزیکی و بار واقعی کاربران اندازه‌گیری نشده‌اند.

در اجرای این تغییر، ۳۶۴ تست JavaScript و ۲۸ تست PHP با ۲۷۹ assertion گذشتند. اعتبارسنجی ۱۲ شخصیت و ۷۲ نسخهٔ اطلس، release، لایه‌های UI، تمامیت راهنماها و تک‌باندل تولید نیز موفق بود. مسیر منو، نام نمایشی، انتخاب تیام، شروع و پرش، پایان دور و حضور امتیاز ۹۷ در جدول دستگاه در Chrome مشاهده شد. بررسی عرض موبایل با قاب مرورگر انجام شد؛ تست دستگاه فیزیکی یا اندازه‌گیری نرخ فریم نیست. اسکریپت Playwright مستقل در این محیط به‌علت بسته‌شدن صفحه کامل نشد و به‌عنوان تست موفق گزارش نشده است.

برای مسابقه یا عرضهٔ بزرگ، گام بعدی تست هم‌زمانی روی MySQL واقعی، تست بار متناسب با تعداد کاربران، پایش خطا و نسخه، حساب کاربری قابل بازیابی و آزمون انسانی سختی است. این موارد با «بدون نقص» یا «کلاس جهانی تأییدشده» جایگزین نشده‌اند.
