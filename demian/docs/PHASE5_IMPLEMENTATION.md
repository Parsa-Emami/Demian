# Phase 5 — Phaser Game Core

The core is framework-adapter based so domain code can be tested without a browser. `PhaserGameCore` is the composition root: it wires `SceneManager`, `AssetLoader`, `AnimationRegistry`, `CharacterSystem` and `GameRuntimeManager` without importing Phaser in domain modules. `SceneManager` owns registration, active-scene switching, shutdown and destruction. `AssetLoader` de-duplicates loaded and in-flight keys, supports image/atlas/json/audio files, and resolves Phaser Loader `complete`/`loaderror` events. `CharacterSystem` owns definitions and live sprites and removes listeners, stops animation and destroys sprites on despawn. `AnimationRegistry` makes animation creation idempotent. `ObjectPool` recycles short-lived objects with bounded capacity and explicit destruction. `MemoryCleanup` tracks EventEmitter listeners and TimerEvents. `GameRuntimeManager` composes scene disposers and guarantees idempotent shutdown.

Phaser-specific objects are passed in from the composition root. This follows Phaser's scene lifecycle and explicit GameObject destruction model (see the official API documentation: https://docs.phaser.io/api-documentation/class/scenes-systems and https://docs.phaser.io/api-documentation/class/gameobjects-gameobject).
