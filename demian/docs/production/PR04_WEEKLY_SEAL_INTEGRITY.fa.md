# PR 04 — محافظت از Snapshot قطعی هفتگی

`WeeklySealAudit` فقط خواندنی است و هیچ امتیاز یا کوپنی تولید نمی‌کند. در عملیات مجدد `WeeklySettlementService::seal`، پیش از بازگرداندن `already_sealed` این شروط بررسی می‌شوند:

- SHA-256 محتوای کامل Snapshot، تعداد شرکت‌کنندگان و فهرست موجود برندگان باید با اطلاعات قفل‌شدهٔ دوره برابر باشد.
- هر برنده باید به یک رکورد فنی مرتبط با همان بازی، نسخه قانون، بازیکن، Run، امتیاز، زمان و رتبه اشاره کند.
- رتبه جایزه برای هر بازی باید مثبت و یکتا باشد.
- هر ناسازگاری خطای قاطع می‌دهد، بدون بازنویسی فصل، انتشار امتیاز تازه، یا تولید/اصلاح کوپن.
- راهکار نسخهٔ اولیه از الگوریتم JSON و ترتیب فیلدهای فصل 7b محافظت می‌کند و برای دوره‌های قدیمی نیازمند مهاجرت داده نیست.

**محدودیت:** این کنترل، دست‌کاری عمدی توسط کسی که دسترسی مدیریتی کامل به DB و توان بازنویسی digest دارد را به‌تنهایی کشف نمی‌کند. برای انتشار تجاری به بکاپ خارج از میزبان، لاگ جداگانه و بررسی مستقل رویدادهای برنده نیز نیاز است. فعال‌سازی جایزه انجام نشده است.
