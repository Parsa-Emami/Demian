# PR 03 — امنیت حساب و بازیابی بدون OTP

- تغییر رمز عبور، توکن Bearer قبلی را در همان تراکنش MySQL باطل می‌کند؛ UI پاسخ با توکن جدید را فقط در `sessionStorage` نگه می‌دارد و هیچ رمز عبوری ذخیره نمی‌شود.
- هر درخواست تغییر رمز پس از قفل ردیف، اعتبار توکن فعلی را دوباره بررسی می‌کند تا Race بین تغییر رمز و چرخش نشست باعث اعطای مجوز ناخواسته نشود.
- صرفاً دارنده **کد پشتیبان یک‌بارمصرف بلندمدت** می‌تواند همراه درخواست بازیابی، `new_password` بدهد و بدون پیامک رمز را بازنشانی کند. لینک بازیابی کوتاه‌مدت اجازه reset رمز نمی‌دهد.
- Rate Limit تماس برای تلفن با `0910...` یا `+98910...` و قالب‌های معادل یک کلید HMAC/Hash واحد می‌سازد و با سهمیه IP ترکیب می‌شود.
- اطلاعات کد پشتیبان، رمز، و توکن هرگز به URL یا تلِمتری نمی‌روند. دریافت کد پشتیبان جدید پس از بازیابی ضروری است.
- وضعیت `phone_verified` و قوانین مالی تغییر نکرده‌اند؛ ورود بدون OTP هرگز واجد شرایط بودن کوپن را اثبات نمی‌کند.
- نیازمند اجرای تست‌های PHP SQLite/MySQL، JS، صفحه ورود و بازیابی روی مرورگر واقعی و Staging است؛ deploy واقعی انجام نشده است.
