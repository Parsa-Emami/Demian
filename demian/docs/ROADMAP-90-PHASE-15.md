# Phase 15 — Referral & Customer Acquisition (source candidate)

Stacked on Phase 14. Disabled by default: DEMIAN_REFERRALS_ENABLED=false, requires configured OTP. The feature never generates coupons, currency, spendable XP, leaderboard points or cash. A separate nontransferable recognition score awards 10 points per qualified registration; at most 10 per verified inviter and 100 system-wide per Tehran calendar month. No monetary activation is implemented. Cost of these rewards is zero, not total campaign CAC; report explicitly leaves actual CAC unknown until actual marketing/SMS/staff expenditures are measured.

A verified account requests a random 64-bit invitation code through authenticated no-store API. The game panel shares a URL fragment so the invitation is not sent in HTTP URL logs. Registration asks for confirmation; the code is attributed only during new account creation, in the same transaction, never on existing accounts. Invalid codes roll back, and the user can register without a code. No contact lists, third-party share pixels or public identity lookup. Status is private; admin dashboard requires existing global-report permission and exposes aggregates only. Privacy export includes incoming status, deletion cascades personal attribution and removes codes; inviter deletion nulls the relationship. Keyed, non-public award digests expire after 90 days and preserve monthly budget even following deletion. No phone/device data is exported. Before enabling, update reviewed privacy disclosures to cover the limited award digest retention.

Qualification requires two distinct verified numbers, recent installation evidence for both accounts with no observed overlap, 48-hour aging and positive server-verified replay on two Tehran days, linked to sealed weekly progress and started after verification/registration. No client score or status input. Missing evidence is pending; shared device or duplicate recipient digest is review-only, not a ban. Pending invitations expire after 30 days; no automatic approval from review. Limits and exact-once marker are serialized with an InnoDB singleton transaction; immutable reward marker unique per invitee digest for its retention window. Multiple SIMs and different devices still do not prove human uniqueness; no financial reward is safe until separately reviewed. Cron examines at most 100 pending records per run and prunes expired digests; use persistent shared cache + scheduler. Manual command: php artisan arcade:referrals:evaluate. The aggregate report is at /cashier/admin/referrals.

Applied local game-ui-ux skill: responsive native disclosure, explicit sharing and account lifecycle reset; no engine changes. Static frontend rebuild belongs to existing CI. QR rendering, real CAC tracking, explicit review resolution UI and complete positive-path and browser acceptance are outstanding; no external QR service added. Physical device/OTP and legal review, production art and previous phase acceptance remain mandatory. No deployment or real coupon issuance.
